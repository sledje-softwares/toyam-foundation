## Gaps (open)

### Blocking the workflow

1. **No way to complete a field task.** The field app has no "task done" action and there is no office RPC; approval requires no open task. In the run the two tasks were completed with the service role. Needs a field-app action (and/or `complete_field_task` for the office, the known DB gap). **Resolved 2026-11-19:** `complete_field_task` (operator in the app: thread menu "Mark task done"; office: "Mark complete" on `/tasks/[id]`), migration `20261119100000_task_complete_case_close.sql`.
2. **Report sender (8.2) does not exist.** `request_report_send` queues rows and `_shared/send` builds the mail, but nothing calls `claim_report_send`; email submissions may only be recorded by the sender, so an email insurer case cannot reach `submitted` except as channel `other`. *(2026-11-19: built, not deployed — edge function `report-send`, test mode by default; see its README.)*
3. **No pipeline worker (D38)** and **no OCR engine**: labels need the worker (here Claude by hand); OCR / field suggestions never run, so tap-to-fill and number suggestions are empty.
4. **No close action** after the insurer's acknowledgement (no RPC moves `submitted` → `closed`). **Resolved 2026-11-19:** `close_case` ("Close case…" on `/submissions`; P7), same migration.

### Field app

5. **Composer overflow:** with ~13+ attached files the file list pushes the caption box and Send off-screen and does not scroll — the operator cannot send. Worked around by removing files and sending twice. **Addressed 2026-11-19 (not yet on a device):** the picked-file list is at most ~4 rows tall and scrolls, with a "13 files · sent as 1 message" line (`src/ui/Composer.tsx`).
6. **Thread does not refresh after delivery:** the sent message disappears from the thread when it leaves the outbox and shows again only after reopening the case (no refetch / realtime on own messages). **Addressed 2026-11-19 (not yet on a device):** one bubble per message keyed by client_message_id; stored items kept app-wide until the server copy is fetched; refetch ~1 s after delivery; rows keep their order (docs/11 'Thread attachments').
7. Sent messages show **no file thumbnails, count or ✓/✓✓ ticks** in the thread. **Addressed 2026-11-19:** 384 px thumbnails, file chips, 1600 px viewer, 'N files', ✓/✓✓/blue ✓✓ with the state in place; migration `20261119810000_field_thread_files.sql` (push to hosted).
8. **Task instructions and location are never shown** to the operator (only the title in the system message).
9. The operator's **own message raises the unread badge** on the case list. **Addressed 2026-11-19:** the server never counted own messages; the app never marked threads read — now `mark_thread_read` while the thread is open, plus local read marks.
10. Gallery files arrive with picker names (`1000243251.jpg`), not the album file names.
35. **Device OCR (planned "result sent with the file") was never built.** **Addressed 2026-11-19 (phone part):** ML Kit on the 1600 px copy of every photo (Latin + Devanagari, bundled), Aadhaar masked, short description from the tag + text, `record_device_ocr` (`20261119600000_device_ocr.sql`), shown to staff in the report panel and the case evidence list (docs/11 "Device OCR and description"). Server OCR (PaddleOCR) for insurer attachments and low-confidence photos stays with the pipeline worker (gap 3).

### Found on review of the whole session (2026-11-19)

Numbering continues; severity **B** blocks the workflow, **M** wrong or lost data / blocks a role, **L** friction or polish, **D** developer / operations.

**Intake and templates**

23. **M** — ICICI template has **no chassis / engine number fields**, although the insurer's intimation sheet carries both (`Engine No`, `Chassis No`); the chassis photo could only be matched to `make_model`. Add the fields (intake extract + report rows) as a new template version.
24. **L** — Vehicle number comes from the subject without dashes (e.g. `MP01AB1234`) while the table has `MP-01-AB-1234`; no normalisation of registration numbers.
25. **L** — Joined values lose meaning: ICICI `contact_person` became two phone numbers with no name; IndusInd `policy_period` became `14-Feb-2026, 13-Feb-2027`.
26. **M** — Files labelled by **file-name rule skip the LLM, so they get no field matches** (docs/10 says the field matches still need the call). Insurer DL / policy / chassis attachments are therefore never offered beside their fields or for tap-to-fill. **Addressed 2026-11-19:** per-template category → field map (`config/templates/maps/*.yaml`, `case_template_category_fields`, migration `20261119500000_category_field_map.sql`, `npm run maps:check -w services/intake`); labelled files get `category_map` field matches. Maps are `reviewed: false` until the office reviews them. Hosted: push the migration, `templates:load` (new versions), then `backfill_category_field_matches()`; cases pinned to older template versions get no map (rule 8).
27. **L** — `intake_config()` is cached for 5 minutes in the function; insurer-domain or template changes take up to 5 minutes (and a function restart locally) to apply. Document it.
28. **L** — Intake via the hourly IMAP poll took up to an hour; push (Email Routing) exists only on the developer's test subdomain until Q14. The run exercised the poll path only.
29. **D** — The local seed uses placeholder insurer domains (`indus-general.example`, `lombard-sample.example`), so real-shaped mails are `unmatched` locally until the domains are changed by hand.

**Field app**

30. **M** — **Upload failures are invisible to the operator**: during the R2 outage the message said only "Saved on this phone" with no error, retry count or reason; the outbox screen is not reachable from the thread menu (menu has only Checklist). *(2026-11-19: Outbox in the case-list and thread ⋮ menus; per-message reasons with Retry in the thread.)*
31. **D** — **No server-side signal when device uploads fail**: `evidence-upload` answered 200 (signing worked) while every PUT to R2 failed; nothing alerted. Use `report_outbox_status` / `case_outbox_status()` to alert the office or orchestrator when items stay queued.
32. **L** — Gallery files are uploaded byte-for-byte (no recompression), so large gallery photos cost bandwidth and storage (D18 says no marking or blocking; size policy for gallery files is open).
33. **L** — The system photo picker opens inside the last album; selecting by visual grid is error-prone (no file names shown).
34. **D** — The release APK on the phone was built from an uncommitted tree; APK builds are not traceable to a commit (record commit hash / version in the build).

**Labelling**

35. **M** — 384 px is too small for document screenshots (the DL portal extract was unreadable); these depend on `needs_detail` → OCR, and there is no OCR yet (gap 3). A low-confidence document should go straight to escalation or a 1600 px read. **Addressed 2026-11-19 (code; needs an APK to try):** ML Kit OCR (Latin + Devanagari, offline) on the phone's 1600 px copy, stored in `evidence_ocr` (`mlkit_device`, `summary` description, `source_width`), Aadhaar-like numbers masked on the phone and in SQL (`record_device_ocr`, migration `20261119600000_device_ocr.sql`); the pipeline adds an OCR excerpt to the label request and skips server OCR when device OCR is present.
36. **D** — Real labelling is blocked on the client's approval to send images to a provider (Q21) and an API key; until then labels need a person or agent (the `manual` mode).

**Reports**

37. **M** — Generated **Word files were not checked** (only produced and stored). Open them in Word / LibreOffice against the insurer samples.
38. **L** — Insurer attachments are placed in report photo sections at whatever resolution the insurer sent (no relevance pass by default); the office must mark irrelevant files before generating.
39. **L** — "Discrepancy observed" (ICICI) prints entirely in bold; check against the sample report whether that is intended.

**Deployment and operations**

40. **D** — The retired `report-generate` edge function (D51: Browser Rendering dropped) is still deployed on hosted; remove it.
41. **D** — Hosted Auth open sign-up was enabled at last check (`disable_signup:false`); turn it off.
42. **D** — `INTAKE_SECRET` is stored nowhere but the two platforms; a mail could not be posted to `intake` directly for testing. Keep operational secrets in a password manager.
43. **D** — Only one admin exists and its password is not held by the developer; test logins had to be created with the service role, bypassing `admin-users`. Add a second admin / break-glass procedure.
44. **D** — The web deploy relies on shell variables overriding `apps/web/.env.local` (which points at the local stack); a `deploy:hosted` script with the hosted values and `NEXT_PUBLIC_FIELD_SIGN_IN` would make it repeatable. Next.js warns that `middleware` is deprecated in favour of `proxy`.
45. **D** — Field uploads cannot be tested on the local stack: the R2 presigner is hard-wired to `*.r2.cloudflarestorage.com` (no endpoint override for a local S3 such as Supabase Storage's S3 endpoint), and `supabase/functions/.env` has no example file (INTAKE_SECRET, PUBLIC_SUPABASE_URL, R2_*).
46. **D** — Browser automation could not reach the web app (extension disconnected; no test-labelled host). Gap 21 stands until a person signs in or a staging host exists.
